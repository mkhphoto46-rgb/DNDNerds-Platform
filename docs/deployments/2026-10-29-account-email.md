# Account email and session request cleanup

Resend sending key was present on the VPS, but EMAIL_PROVIDER and EMAIL_FROM were missing. The deployed API also lacked the Resend adapter. A direct send to the official Resend delivered@resend.dev simulator was accepted with HTTP 200 before activation.

Published only the reviewed API email adapter/registry/policy/guard files, then enabled the sender through a dedicated systemd EnvironmentFile. The private application .env, VTT backend/index and public support settings were fingerprint-checked unchanged. Initial guarded release backup: /opt/dndnerds/backups/account-email-20261029T202453Z. Initial web build: rgWlX3gr0bzbrMqgDLF01.

The final web release adds one shared, short-lived in-memory session request for header, mobile account controls, social dock, game hub, account, feedback, checkout and auth forms. Concurrent consumers share a network request, independently readable responses, and a 30-second cache. Auth events invalidate before consumers refresh; cross-tab events use one BroadcastChannel listener. Login and registration session checks force a fresh lookup. Server failures are not cached. XP is gated by session state; known guests do not send XP heartbeat requests. Generation checks reject stale XP headers and parsed bodies after auth changes.

Validation:
- Seven unit tests passed, including forty concurrent session consumers, invalidation during an in-flight request, guest caching, expiration, failure recovery, Resend request formatting/failure rejection and activation policy.
- API and web production builds and web typecheck passed.
- Independent review found one XP body parsing race; it was corrected before the final web release.
- Production HTTP flow using one disposable simulator account passed registration email acceptance, blocked unverified login, token confirmation, replay rejection, automatic ACTIVE/email_verified state, login cookie, password-reset email request, password reset, previous-session revocation, old-password rejection, new-password login and logout. The test account was removed afterward. Confirmation/reset tokens for route checks were generated by the production token helper and never printed; this does not claim the original outbound message was opened in a real mailbox.
- The sole active primary administrator had an unverified email. A fresh verification link was sent to that existing account using the production provider; Resend accepted it. No bulk emails were sent to other pending accounts.

Email acceptance by Resend does not prove Inbox placement. Legitimate 401 responses for unauthenticated session discovery, invalid credentials or revoked sessions remain. This change reduces duplicate network requests; it does not cap the whole application's API inventory at an arbitrary number or remove authentication safeguards.
